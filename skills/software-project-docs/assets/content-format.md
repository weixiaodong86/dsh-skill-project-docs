# 内容源格式（受控 Markdown）

内容源是唯一的编辑对象。改内容就改 `.md`，再重建 DOCX；不要直接改 DOCX，否则下次重建会丢改动。

## 1. front matter

文件开头两行 `---` 之间为元信息：

| 字段 | 必填 | 说明 |
|---|---|---|
| `project` | 是 | 项目名称，用于封面与页眉 |
| `project_code` | 是 | 项目编号，用于文档编号 |
| `doc_code` | 是 | 文档编号，格式 `{项目编号}-{文档代码}` |
| `title` | 是 | 文档名称，用于封面、页眉、文件名 |
| `version` | 是 | `V1.0` 形式 |
| `date` | 是 | `2026-11-21` 或 `2026年11月21日` |
| `classification` | 否 | 公开／内部／秘密／机密，默认"内部" |
| `issuer` | 否 | 编制单位 |
| `author` / `reviewer` / `approver` | 否 | 编制人／审核人／批准人 |
| `mode` | 否 | `formal`（默认）或 `template` |
| `layout` | 否 | `full`（默认，封面＋目录）或 `brief`（短文档：标题块＋修订记录） |
| `revisions` | 是 | 修订记录行，见下 |

`revisions` 每行格式：`- 版本 | 日期 | 修订人 | 修订说明`，可加第五列审核人：

```yaml
revisions:
  - V1.0 | 2026-11-21 | 张三 | 首次发布 | 李四
  - V1.1 | 2026-11-28 | 张三 | 补充 4.2 性能指标与验证方式 | 李四
```

没有 `revisions` 时，构建库自动按"当前版本 + 首次发布"生成一行。

## 2. 块语法

| 写法 | 渲染结果 |
|---|---|
| `# 引言` | 一级标题，自动编号"1 引言" |
| `## 编写目的` | 二级标题"1.1 编写目的" |
| `### 业务背景` | 三级标题"1.1.1 业务背景" |
| 普通段落 | 正文（宋体小四、首行缩进 2 字符、1.5 倍行距） |
| `- 条目` | 无序列表（●） |
| `1. 条目` | 有序列表（（1）（2）…） |
| `表: 名称` | 下一张表的表题，自动编号"表{n}-{m}" |
| `表: 名称 \|\| 10,20,30` | 同上，并按比例分配列宽（比例和自动归一） |
| `\| 列1 \| 列2 \|` | 表格；第二行 `\| --- \| --- \|` 为分隔行，可省略 |
| `图: 名称 \|\| 路径.png \|\| 12` | 图片＋图题，宽度 12 cm（默认 14.5 cm） |
| `![名称](路径.png){width=10cm}` | 等价的图片写法 |
| `:::fill 说明文字` … `:::` | 模板填写说明（楷体斜体灰字，前缀"【填写说明】"） |
| `:::example 示例文字` … `:::` | 模板示例（楷体斜体，首段前缀"示例："） |
| `:::note 注解` … `:::` | 正式注解（宋体五号，前缀"注："） |
| ```` ``` ```` 代码块 ```` ``` ```` | 等宽字体，左缩进 1 cm |
| `# 附录 A 名称` | 附录标题，不参与章节编号；表、图编号改用附录字母 |
| `**加粗**` | 段内加粗（仅正文与表格单元格） |

连续的非空行会合并为一个段落（中文换行不产生空格）。空行分隔段落。

## 3. 编号：不要手写

- 章节号、表号、图号由构建库自动生成，内容源里**不写**"1." "表3-1"；
- 引用其他章节时写文字描述（"详见第 4 章"），不写具体编号，避免重排后失效；
- 附录用 `附录 A`、`附录 B` 开头，编号自动变为 `表A-1`、`图A-1`。

## 4. 图片

- 路径相对**内容源文件**所在目录，或写绝对路径；
- 支持 PNG、JPG；建议宽度 1400 px 以上；
- 找不到文件时渲染为红色占位文字`［图片缺失：路径］`，不中断构建。

## 5. 表格约定

- 每行列数一致；不足时补空单元格，不要少写竖线；
- 单元格内不换行；需要多段时用"①②③"连续书写；
- 表格里可以写 `**加粗**`；
- 宽表（超过 6 列）建议减小字号内容或拆表，正文宽度只有 15.5 cm。

## 6. 模板模式的写法

```markdown
## 建设目标

:::fill 说明本系统的建设目标与业务价值，控制在 150 字以内，依据项目建议书第 2 章。
:::

:::example 建成后实现园区企业入驻、缴费、报修全流程线上办理，人工窗口业务量下降 40%。
:::
```

说明在前、示例在后；说明写"填什么 + 粒度 + 依据"，示例必须自洽。

## 7. 预览与排错

| 现象 | 原因与处理 |
|---|---|
| 表格错列 | 某行少了 `|`，补齐列数 |
| 表题跑到表外 | `表:` 行与表格之间不能有空行 |
| 标题编号重复 | 内容源里手写了编号，删掉 |
| 图片不显示 | 路径错或文件不存在，改相对路径 |
| 列表变成正文 | `-` 后必须有空格 |
