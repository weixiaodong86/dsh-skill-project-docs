# 版本与修订

## 1. 版本号规则

格式 `V{主版本}.{次版本}`，只升不降、不跳号、不复用。

| 场景 | 版本变化 | 示例 |
|---|---|---|
| 新建文档 | 从 `V1.0` 起 | V1.0 |
| 评审稿（未发布） | 次版本递增 | V0.1 → V0.2 → V1.0 |
| 内容修订：补充、修正、细化，章节结构不变 | 主版本不变，次版本 +1 | V1.0 → V1.1 |
| 结构调整、范围变更、需求增删 | 主版本 +1，次版本归零 | V1.1 → V2.0 |
| 勘误（错别字、标点、格式） | 次版本 +1，与内容修订同样处理 | V1.0 → V1.1 |
| 合并多份文档 | 主版本 +1 | V3.0 |

同一版本号只能对应一个文件内容；文件改了就必须升版本，不允许"同名覆盖"。

## 2. 文件命名与目录

```
docs/
├─ _source/                                   # 内容源（受控 Markdown）
│  └─ YQ-2026-001-REQ-SRS_V1.1.md
├─ _manifest.json                             # 版本登记（内部使用，不交付）
├─ YQ-2026-001-REQ-SRS_V1.0.docx             # 历史版本，保留
└─ YQ-2026-001-REQ-SRS_V1.1.docx             # 当前版本
```

- 文件名：`{文档编号}_{版本号}.docx`，例如 `YQ-2026-001-REQ-SRS_V1.1.docx`。
- 文档编号：`{项目编号}-{文档代码}`，文档代码见 `catalog/overview.md`。
- 不使用空格、中文括号、"最终版""最新版""改后"等字样。
- 旧版本原样保留；作废版本在 `_manifest.json` 标记 `status: 作废`，文件不删除。

## 3. 修订记录表

每份文档前置部分固定一张，首次发布也要有第一行：

| 版本号 | 日期 | 修订人 | 修订说明 | 审核人 |
|---|---|---|---|---|
| V1.0 | 2026-11-21 | 张三 | 首次发布 | 李四 |
| V1.1 | 2026-11-28 | 张三 | 补充 4.2 性能指标与验证方式 | 李四 |

要求：

- 按时间正序，保留全部历史行；
- "修订说明"一句话，写**改了什么**，不写**为什么改**、不写过程、不写"根据意见"；
- 修订人与封面"编制"一致；审核人与封面"审核"一致；
- 版本号与封面、页眉、文件名一致。

## 4. 修订执行步骤

1. **定位**：确认要改的文档编号、当前版本、内容源路径；没有内容源时，按旧 DOCX 重建内容源（只重建结构与已定稿文字）。
2. **确认范围**：列出将改动的章节，请用户确认；不明确时先问，不整篇重写。
3. **改内容源**：只改目标章节，其余文字保持原样；随手发现的错误单独列给用户，不擅自扩大改动。
4. **升版本**：按第 1 节规则确定新版本号。
5. **追加修订记录**：在 front matter `revisions` 末尾加一行，格式 `版本 | 日期 | 修订人 | 修订说明`。
6. **重建新文件**：输出到新文件名，旧文件不动；构建命令见 `SKILL.md`。
7. **自检与登记**：`check_docx.py` 通过后，更新 `_manifest.json` 的版本、日期、文件名。

## 5. 版本登记文件

`docs/_manifest.json` 是内部台账，**不随文档交付**，用于回答"现在最新是哪一版、改过什么"：

```json
{
  "project": "智慧园区综合管理平台",
  "project_code": "YQ-2026-001",
  "updated": "2026-11-28",
  "documents": [
    {
      "doc_code": "YQ-2026-001-REQ-SRS",
      "title": "软件需求规格说明书",
      "version": "V1.1",
      "date": "2026-11-28",
      "file": "docs/YQ-2026-001-REQ-SRS_V1.1.docx",
      "source": "docs/_source/YQ-2026-001-REQ-SRS_V1.1.md",
      "status": "已发布"
    }
  ]
}
```

`status` 取值：`草稿`、`评审中`、`已发布`、`作废`。

## 6. 批量修订

多份文档同一轮修订时：

- 统一修订日期与修订人；
- 各文档独立编号，不共用版本号；
- 先改被引用的上游文档（需求 → 设计 → 测试），再改下游，避免引用失真；
- 最后逐份自检，汇总一张修订台账回复用户。

## 7. 禁止事项

- 不覆盖旧文件，不删除历史版本；
- 不在正文写"本版修改说明"章节替代修订记录表；
- 不在修订记录里写"AI 修订""由助手修改"；
- 不把未完成的草稿标为"已发布"；
- 不同文档之间不复制同一段修订说明而不核对内容。
