# 文档集总览

18 类过程文档，覆盖软件研发从立项到结项的全流程。生成时按依赖顺序推进，后一份引用前一份而非复制。

## 2. 依赖关系

```
①立项报告
   └─②项目管理计划
        ├─③需求规格说明书
        │    ├─⑧概要设计说明书
        │    │    └─⑨详细设计说明书
        │    │         └─⑦测试计划
        │    └─⑦测试计划
        ├─④质量保证计划
        ├─⑤配置管理计划
        └─⑥风险管理计划
              └─⑬风险登记册

执行期：⑩周报/月报、⑪会议纪要、⑫变更请求单、⑬风险登记册 相互支撑
收尾期：⑭测试报告 → ⑮部署上线方案 → ⑯用户手册 → ⑰验收报告 → ⑱项目总结报告
```

## 3. 推荐生成顺序

1. ①立项报告 → ②项目管理计划
2. ③需求规格说明书 → ⑧概要设计 → ⑨详细设计
3. ④质量保证、⑤配置管理、⑥风险计划（可与 2 并行）
4. ⑦测试计划 → ⑭测试报告
5. ⑮部署上线方案 → ⑯用户手册
6. ⑰验收报告 → ⑱项目总结报告
7. ⑩⑪⑫⑬ 贯穿执行期，按实际发生逐份生成

## 4. 按项目规模裁剪

| 规模 | 建议文档集 | 说明 |
|---|---|---|
| 小型（≤3 人月） | ②③⑦⑭⑰⑱（6 份） | 计划、需求、测试计划、测试报告、验收、总结 |
| 中型（3–12 人月） | 上表 6 份 + ①④⑤⑥⑧⑨⑮⑯（14 份） | 补立项、三份计划、设计与上线 |
| 大型（>12 人月） | 全部 18 份 | 加周报/纪要/变更/风险台账 |

裁剪只减少文档种类，不减章节：留下来的文档仍按完整骨架写。

## 5. 命名与编号

- 文档编号：`{项目编号}-{文档代码}`，例 `YQ-2026-001-REQ-SRS`；
- 文件名：`{文档编号}_{版本号}.docx`，例 `YQ-2026-001-REQ-SRS_V1.1.docx`；
- 同类文档多份时加序号：`RPT-STATUS-202611`（按周期）、`RPT-MIN-20261121-01`（按日期场次）、`CHG-REQ-001`（按流水）。
